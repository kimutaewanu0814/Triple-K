# 첫걸음

## 휴대폰에서 열기

PC와 휴대폰을 같은 Wi-Fi에 연결한 뒤 `휴대폰으로 열기.cmd`를 실행하세요.
또는 `.\.venv\Scripts\python.exe start_mobile.py`로 실행할 수 있습니다.
휴대폰 브라우저에서 `http://PC의-Wi-Fi-IPv4주소:5001`을 여세요.
PC의 IPv4 주소는 PowerShell의 `ipconfig`로 확인할 수 있고 네트워크가 바뀌면 달라질 수 있습니다.
PC가 켜져 있고 서버가 실행 중이어야 합니다. Windows 방화벽 알림이 나타나면 신뢰하는 네트워크에서 접근을 허용하세요.
이 실행 방식은 같은 네트워크에 앱을 공개합니다. 할 일 내용은 OpenAI에 전송되며 다른 이용자의 호출에도 서버의 API 키가 사용됩니다.

과제를 시작하기 어려운 대학생이 작은 행동부터 시도하도록 돕는 Flask MVP입니다.
할 일 입력 → Flask → OpenAI API → 행동 카드 3개의 흐름을 구현했습니다.
기본 행동 제안은 로그인 없이 이용할 수 있습니다. 걸음을 기록하면 할 일 이름과 완료 개수를 이 브라우저에 로그인 계정별로 저장합니다. 로그인 전 기록은 별도로 유지합니다. 기기 간에 이어 할 행동을 동기화하려면 Firebase 설정과 Google 로그인이 필요합니다.

## 현재 파일 구성

```text

├── README.md

└── tests/
    ├── test_app.py         # Flask/API 응답 처리 모의 테스트
    └── test_ui.cjs         # JavaScript 화면 로직 모의 테스트
```

로컬의 `.preview.html`은 최신 화면을 확인하기 위한 정적 미리보기이며 Git에서 제외됩니다.
파일을 직접 열면 서버 API를 사용할 수 없으므로, 행동 생성과 난이도 변경은 Flask 접속 주소에서 확인하세요.

## 구성

- Python 3.10 이상, Flask, 순수 HTML/CSS/JavaScript
- LLM 제공자: **OpenAI** / 기본 모델: **gpt-4.1-mini**
- API 키는 특정 모델을 고정하지 않습니다. 서버가 `OPENAI_MODEL` 값으로 요청 모델을 선택합니다.
- 2026-11-09 실제 키로 짧은 테스트 요청을 보낸 결과, 요청 모델 `gpt-4.1-mini`의 응답 모델은 `gpt-4.1-mini-2025-04-14`였습니다. 같은 모델의 구체적인 버전명이므로 설정은 변경하지 않았습니다.
- `OPENAI_MODEL`로 모델 변경 가능. Chat Completions 및 Structured Outputs를 지원하는 모델이 필요합니다.
- JSON Schema의 `strict: true`와 Pydantic 서버 검증을 함께 사용합니다.
- 정상 결과는 행동 정확히 3개, 시간은 2~5 사이 정수입니다. 시간은 전체 과제의 완료 시간을 뜻하지 않습니다.

## Windows PowerShell 실행

Python 3.10 이상이 설치되어 있어야 합니다. `py`가 없고 `python`만 있으면 아래 `py`를 `python`으로 바꾸세요.

```powershell
cd D:\codex\first-run\first-step
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

`.env`의 `OPENAI_API_KEY=` 뒤에 본인의 키를 입력해 저장하세요. `.env`는 Git에서 제외됩니다.
모델과 학교 링크도 같은 파일에 설정할 수 있습니다.

키를 화면에 표시하지 않고 저장하려면 메모장 대신 다음 도구를 한 번 실행하세요.

```powershell
.\.venv\Scripts\python.exe setup_key.py
```

입력한 키는 로컬 `.env`에 저장되므로 컴퓨터를 껐다 켜도 다시 입력할 필요가 없습니다.
키 입력 시 화면에는 아무 글자도 표시되지 않습니다. 붙여넣은 뒤 Enter를 누르세요.
이 도구는 키와 사용 종료일을 설정하며, 모델명·학교 링크 등 다른 설정은 유지합니다.
`.env`에는 키가 평문으로 저장되므로 이 파일을 공유하거나 Git에 추가하지 마세요.
재부팅 후에는 서버 실행 명령만 다시 실행하면 됩니다. 서버의 자동 시작은 포함하지 않습니다.

```dotenv
OPENAI_API_KEY=여기에_본인의_키_입력
OPENAI_MODEL=gpt-4.1-mini
OPENAI_API_ACTIVE_UNTIL=2026-12-15
CAMPUS_SUPPORT_URL=
```

`OPENAI_API_ACTIVE_UNTIL`은 한국 시간 기준 사용 가능한 마지막 날짜입니다.
기본값은 **2026-12-15**이며, **2026-12-16 00:00부터** 모든 AI API 요청을 차단합니다.
날짜 형식이 잘못되면 호출을 허용하지 않고 설정 오류를 표시합니다.
종료일 이후에도 메인 화면과 전문 지원 안내는 열립니다. 종료 직전에 시작한 요청은 완료될 수 있습니다.
이는 이 앱의 호출 제한이며 OpenAI 계정의 키 자체를 만료·폐기하지 않습니다.
다른 앱에서도 키 사용을 중단하려면 종료 후 OpenAI의 API 키 관리 화면에서 해당 키를 폐기하세요.
[OpenAI API 키 관리 안내](https://developers.openai.com/api/docs/guides/api-keys)

건양대학교 학생상담센터 주소가 기본으로 설정되어 있어 별도 입력이 필요하지 않습니다.
`CAMPUS_SUPPORT_URL`을 비워도 https://kyucounsel.konyang.ac.kr/kyucounsel.do 링크가 표시됩니다.
다른 공식 상담센터로 변경할 때만 이 설정을 수정하세요. http/https 주소만 허용합니다.
전문 지원 안내에는 정신건강 위기상담전화, 보건복지상담센터, 자살예방 상담전화도 표시됩니다.

가상환경 활성화 없이 아래 명령으로 실행할 수 있습니다. PowerShell 실행 정책 변경이 필요하지 않습니다.

```powershell
.\.venv\Scripts\python.exe app.py
```

접속: **http://127.0.0.1:5000** / 종료: `Ctrl+C`
서버는 로컬 주소에만 바인딩하며 디버그 모드는 꺼져 있습니다. Flask 개발 서버를 사용합니다.

이미 가상환경과 `.env`를 설정했다면 초기 설치는 반복할 필요가 없습니다.
파일 수정 후 실행 중인 서버에서 `Ctrl+C`를 누른 뒤 위 실행 명령으로 재시작하고,
브라우저에서 `Ctrl+F5`로 새로고침하세요. 디버그 모드가 꺼져 있어 서버 코드는 자동으로 다시 로드되지 않습니다.

`.env` 대신 현재 PowerShell 프로세스의 환경 변수로 설정할 수도 있습니다. 같은 항목이 있으면 프로젝트의 `.env` 값이 우선합니다.
`.env`를 저장한 뒤에는 서버 재시작 없이 다음 요청부터 적용됩니다. 상담센터 링크는 브라우저를 새로고침하면 반영됩니다.
메모장에서는 `D:\codex\first-run\first-step\.env`를 열고 저장하세요. `.env.txt` 또는 `.env.example`에 저장한 내용은 읽지 않습니다.
아래 방법만 사용하면 터미널을 닫거나 컴퓨터를 재시작할 때 키 설정이 사라집니다.
재입력을 피하려면 위의 `setup_key.py` 또는 `.env` 저장 방식을 사용하세요.
아래 방식은 API 키를 명령 기록에 직접 적지 않도록 숨김 입력을 사용합니다.

```powershell
$keyInput = Read-Host 'OpenAI API 키' -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', $keyInput).Password
$env:OPENAI_MODEL = 'gpt-4.1-mini'
.\.venv\Scripts\python.exe app.py
```

API 키가 없어도 메인 화면과 전문 지원 안내는 열립니다. 행동 생성은 설정 오류로 안내되며 가짜 결과를 반환하지 않습니다.

## API

`POST /api/split`, `Content-Type: application/json`

```json
{"task":"보고서 작성하기"}
```

`POST /api/refine`: 현재 카드 하나를 같은 형식의 더 쉬운 행동 3개로 교체합니다.
이미 작은 행동이라면 준비 단계나 더 쉬운 시작 행동을 제안하도록 지시합니다.
서버는 상태를 저장하지 않으므로 원래 할 일과 대상 행동을 함께 보내야 합니다.

```json
{
  "task": "보고서 작성하기",
  "step": {
    "title": "보고서 파일 열기",
    "description": "문서 작성 도구를 열고 빈 문서를 준비해요.",
    "minutes": 2,
    "completion_criteria": "빈 문서가 화면에 열려 있어요."
  }
}
```

`POST /api/advance`: ‘쉬워요’ 버튼으로 선택한 행동에서 이어갈 조금 더 도전적인 다음 행동 3개를 제안합니다.
요청 본문은 `/api/refine`과 동일한 `task`, `step` 형식입니다. 시간은 각 2~5분으로 유지하고,
‘쉬워요’를 완료 표시로 취급하거나 행동을 끝냈다고 단정하지 않습니다.

`POST /api/continue`: 화면의 행동 3개를 모두 완료한 뒤 ‘다음 행동 3개 만들기’로 이어갑니다.
요청은 `{task, completed_steps}`이며 `completed_steps`에는 완료한 행동 객체 전체가 정확히 3개 들어갑니다.
각 객체는 위 `step`과 같은 제목·설명·시간·완료 기준을 포함합니다. 원래 할 일과 완료한 행동 3개 전체를 바탕으로,
이미 한 행동을 반복하거나 난이도를 무조건 높이지 않고 다음 행동을 제안하도록 요청합니다. 새 행동도 각 2~5분입니다.
서버는 완료 상태를 저장하지 않으므로 완료 여부는 클라이언트가 전달한 내용에 의존하며, 행동의 개수·자료형·범위는 서버에서 다시 검증합니다.
이 API에도 16KiB 요청 제한, 사용 종료일, 25초 타임아웃과 동일한 오류 처리를 적용합니다.

네 API의 성공 응답은 다음 형태입니다. 아래는 형식 설명용이며 실제 결과로 제공되지 않습니다.

```text
{"steps":[{title, description, minutes, completion_criteria} × 3], "feedback":"피드백 한 줄"}
```

실패 응답: `{"error":{"code":"오류 코드","message":"한국어 안내"}}`

- 400: 빈 입력, 1,000자 초과, 잘못된 JSON·행동
- 403: 한국 시간 기준 API 사용 기간 종료
- 413: 전체 요청 본문 16KiB 초과
- 422: 모델의 응답 거절
- 429: 호출 제한·사용 한도
- 502: 연결·외부 서비스 오류, 잘못되거나 불완전한 모델 응답
- 503: API 키 누락·인증 오류, 종료일 설정 오류
- 504: AI 호출 시간 초과 (SDK 타임아웃 25초, 자동 재시도 없음)

## 화면 동작과 범위

- 카드마다 제목·설명·예상 시간·완료 기준과 ‘어려워요’, ‘쉬워요’ 버튼이 있습니다.
- 카드에서 ‘완료했어요’를 누르면 한 걸음으로 기록되며, ‘완료 취소’로 되돌릴 수 있습니다. ‘이번 행동’에는 현재 카드 3개의 완료 수와 비율이 표시됩니다.
- 행동 3개를 모두 완료하면 **‘이번 행동’ 영역 오른쪽**에 **‘다음 행동 3개 만들기’**가 표시됩니다. 좁은 화면에서는 완료 수 아래로 배치됩니다. 완료만으로 API를 호출하지 않으며, 버튼을 누를 때 다음 행동을 요청합니다. 여기서 마쳐도 괜찮다는 안내를 함께 표시합니다.
- 다음 행동 요청 중에는 중복 클릭과 난이도 변경을 막고 대기 상태를 표시합니다. 성공하면 새 카드 3개로 교체하고 이번 행동 진행률은 0으로 초기화하지만 누적 걸음은 유지합니다. 실패·시간 초과 시 완료한 카드와 완료 표시를 유지하며 재시도할 수 있습니다. 완료 취소 시 버튼을 숨기고, 요청 중 완료 상태나 계정이 바뀌면 이전 응답을 표시하지 않습니다.
- 카드의 ‘해 본 느낌 돌아보기’에서 예상보다 쉬웠는지 선택할 수 있습니다. 완료 전에도 답하거나 건너뛸 수 있으며, 답은 화면에서만 사용하고 걸음 수에 반영하지 않습니다.
- ‘그동안 걸어간 걸음’을 누르면 전체 합계와 할 일별 완료 개수를 가로 막대로 볼 수 있습니다. 처음 완료한 할 일이 한 줄씩 추가되며, 이름이 같은 할 일은 같은 줄에 합산됩니다. 기존 날짜별 기록은 ‘이전 기록 (할 일 이름 없음)’으로 합계에 포함됩니다.
- 걸음 팝업에는 현재 기록의 계정이 표시됩니다. Firebase 프로젝트와 계정 UID별로 브라우저 저장 공간을 나누며, 이메일이나 이름이 바뀌어도 같은 계정의 기록은 유지됩니다. 인증 확인 전에는 공통 기록을 표시하지 않고 완료 기록 버튼을 잠시 비활성화합니다.
- 계정을 바꾸거나 로그아웃하면 걸음 목록과 현재 카드의 완료 표시를 초기화하고 해당 계정 또는 로그인 전 기록을 불러옵니다. 이전 계정의 기록은 삭제되지 않습니다. 같은 계정으로 다시 로그인하면 이 브라우저에 남아 있는 기록을 볼 수 있습니다.
- 기존 브라우저 공통 기록은 ‘로그인 전 기록’으로 보존하며 특정 계정에 자동으로 옮기지 않습니다. 걸음 기록은 기기 간에 동기화되지 않습니다.
- 팝업의 ‘걸음 기록 지우기’를 누르고 확인하면 현재 선택된 계정의 이 브라우저 기록과 현재 카드의 완료 표시만 초기화됩니다. 로그인 전에는 이전 공통 기록을 지우며, 다른 계정의 기록은 유지됩니다.
- 카드를 교체하면 이번 행동 진행률은 초기화되고, 기록한 걸음 수는 남습니다. 완료 취소는 현재 화면에 있는 카드에서 할 수 있습니다.
- ‘어려워요’는 더 쉬운 시작 행동 3개로, ‘쉬워요’는 조금 더 도전적인 다음 행동 3개로 바꿉니다.
- 두 기능 모두 요청 중에는 대상 행동 제목을 표시하고, 성공하면 현재 카드 3개를 교체합니다. 실패하면 이전 결과를 유지합니다.
- 로딩 중 중복 요청 방지, 브라우저 요청 제한 35초, 실패 후 버튼 복구를 구현했습니다.
- 전문 지원 안내는 상단 헤더와 할 일 입력창 바로 위의 강조 배너에서 접근할 수 있습니다. 하단 고정 링크도 항상 표시되며 모두 실제 안내 영역으로 이동합니다.
- 사용자 및 모델 텍스트는 `textContent` 또는 텍스트 노드로만 표시합니다.
- 새로고침하면 입력창과 AI가 제안한 카드가 초기화됩니다. 완료 기록이 있는 할 일 이름과 걸음 수는 계정별로 브라우저에 남고, 사이트 데이터를 지우면 모든 계정의 로컬 걸음 기록이 함께 사라집니다.
- 입력은 OpenAI에 전송됩니다. `store=False`로 요청하며, 제공자 측 데이터 처리는 OpenAI 정책을 따릅니다.
- 원문 입력·응답·예외·API 키는 앱 로그에 남기지 않습니다. 로그에는 고정된 오류 코드만 기록합니다.
- 입력을 작업 데이터로 분리하고 규칙 변경 지시를 무시하도록 프롬프트에 명시했습니다. 의미의 적절성은 모델에 의존하며 형식 검증이 의미까지 보장하지는 않습니다.

전문 지원 안내의 **지역 상담기관** 버튼을 누르면 브라우저에 현재 위치를 한 번 요청합니다. 위치는 Google Places 검색에 전달되며 첫걸음은 저장하지 않습니다. ‘심리상담센터’ 결과 중 좌표가 있는 곳을 직선거리로 비교해 가장 가까운 기관의 Google 지도 상세 화면을 현재 탭에 엽니다. Places 미설정, 위치 확인 실패·거부, 검색 실패·결과 없음에는 시·군·구 직접 검색을 제공합니다.

## 기기 간 동기화 설정

화면 상단의 전문 지원 안내 배너 위에 있는 ‘기기 간 동기화’에서 로그인할 수 있습니다.

1. Firebase Console에서 프로젝트와 웹 앱을 등록합니다. Authentication에서 Google 로그인을 켜고, **Settings → Authorized domains**에 실제 접속할 호스트를 추가합니다. 로컬 테스트용 주소도 사용할 호스트를 등록합니다. 휴대폰과 PC에서 실제로 쓸 때는 두 기기가 접속할 수 있는 HTTPS 주소를 사용합니다.
2. Cloud Firestore의 기본 데이터베이스를 만들고 Rules 탭에 [firestore.rules](firestore.rules)를 적용합니다. 기존 데이터베이스에 규칙이 있으면 해당 `match /firstStepResume/{uid}` 블록을 병합합니다. 규칙은 본인 계정의 문서에만 개별 접근을 허용합니다.
3. 웹 앱 설정의 `apiKey`, `authDomain`, `projectId`, `appId`를 프로젝트의 `.env`에 한 줄 JSON으로 추가합니다. 이 값은 브라우저용 공개 설정이며 Firebase 서비스 계정 비밀 키를 넣는 칸이 아닙니다. 기존 OpenAI·지도 설정은 그대로 둡니다.

```dotenv
FIREBASE_WEB_CONFIG='{"apiKey":"웹 앱 API 키","authDomain":"프로젝트.firebaseapp.com","projectId":"프로젝트 ID","appId":"웹 앱 ID"}'
```

첫걸음 화면의 **기기 간 동기화 → Google로 로그인**을 사용한 뒤, 고른 카드에서 **다음에 이어서 하기**를 누릅니다. 다음 행동을 저장하면 기존 행동을 교체합니다. 같은 계정으로 로그인한 다른 기기에서 **이어서 할 행동**이 표시되며, **저장한 행동 지우기**로 두 기기에서 해당 카드를 지울 수 있습니다. Firestore에는 선택한 카드의 제목·방법·시간·완료 기준과 **원래 할 일(`task`), 완료 여부(`completed`)**를 저장합니다. 나머지 카드와 걸음 수는 이 기능으로 전송되지 않습니다.

- 동기화 설정을 접어도 로그인 계정의 이름·이메일(이메일이 없으면 계정 ID)과 저장 상태가 표시됩니다. 다른 기기에서 행동이 안 보이면 계정이 같은지 먼저 확인하세요. 로그아웃한 뒤 다른 Google 계정으로 로그인할 수 있습니다.
- ‘서버에 저장 중’, ‘서버에 저장했어요’, 불러오기 실패를 구분합니다. 기기에 남은 캐시만 읽은 경우 서버 확인 전임을 표시하고 저장 행동의 완료·조정·삭제를 잠시 막습니다. 저장 실패 시 연결 상태를 확인하고 같은 카드에서 다시 저장하세요.
- 저장한 행동의 **완료했어요**는 완료 여부를 서버에 저장합니다. 다른 기기에서도 완료 표시가 유지되며 중복 클릭·동시 완료는 트랜잭션으로 막습니다. 걸음 수는 완료 요청이 성공한 브라우저에만 1회 기록되며, 이번 행동 3개의 진행률에는 합산하지 않습니다. 완료한 저장 행동은 완료 취소 기능 없이 표시를 유지하며, 다른 행동을 저장하면 새 행동의 완료 여부는 초기화됩니다.
- 저장한 행동의 **어려워요**는 저장된 원래 할 일과 행동을 `/api/refine`에 보내 더 쉬운 행동 3개를 아래 결과 영역에 표시합니다. 기존 저장 행동은 유지됩니다. 새 행동 중 이어서 할 것을 고르고 **다음에 이어서 하기**를 눌러 교체하세요. 실패하면 기존 결과와 저장 행동이 남습니다. 계정이나 저장 행동이 요청 도중 바뀌면 해당 결과를 표시하지 않습니다.
- 이전 형식으로 저장하여 원래 할 일이 없는 행동은 **원래 할 일 → 할 일 연결하기**로 연결한 뒤 난이도를 조정할 수 있습니다. 연결 전에도 완료와 삭제는 가능합니다.

**기존 Firebase 프로젝트에도 변경된 [firestore.rules](firestore.rules)를 적용해야 합니다.** Firebase Console → Firestore Database → Rules에서 이 프로젝트의 `match /firstStepResume/{uid}` 규칙을 반영하고 게시하세요. 이전 규칙은 새 필드를 거부하므로 적용 전에는 저장·완료·할 일 연결이 실패합니다. 다른 데이터의 기존 규칙은 보존하세요.

저장 시 `permission-denied`가 표시되면 위 규칙의 게시 여부와 로그인 계정을 확인하세요. 저장 실패 안내는 이후 빈 데이터 알림이 도착해도 유지되며, 다시 저장을 시도하거나 계정을 바꾸면 초기화됩니다. ‘이 계정에는 저장한 행동이 없어요’만으로는 저장 실패 원인을 확정할 수 없습니다.

로그인 실패 시 화면의 오류 코드를 확인합니다. `auth/unauthorized-domain`은 현재 접속 호스트를 승인된 도메인에 추가하고, `auth/operation-not-allowed`는 Google 로그인 사용 설정을 확인합니다. `auth/popup-blocked`는 브라우저에서 이 사이트의 팝업을 허용합니다.

[Firebase 웹 앱 설정](https://firebase.google.com/docs/web/setup) · [Google 로그인 설정](https://firebase.google.com/docs/auth/web/google-signin) · [Firestore 접근 규칙](https://firebase.google.com/docs/firestore/security/rules-conditions)
